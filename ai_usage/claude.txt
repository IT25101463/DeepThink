Getting the Ingestion Pipeline Started
--------------------------------------------------------------------------------

Me:
ok so i need to write a ingestion pipeline for our project. we have 415 documents in
different formats like pdf docx markdown txt and some scanned pdfs too. how do i
structure this without making seperate scripts for each format type

Claude:
Best approach is a single dispatcher function that routes based on file extension.
You detect the format, call the right parser, and everything returns the same
chunk structure:

    from pathlib import Path

    def parse_document(filepath: Path) -> list[dict]:
        ext = filepath.suffix.lower()
        if ext == ".pdf":
            return parse_pdf(filepath)
        elif ext in (".docx", ".doc"):
            return parse_docx(filepath)
        elif ext == ".md":
            return parse_markdown(filepath)
        elif ext == ".txt":
            return parse_text(filepath)
        else:
            raise ValueError(f"Unsupported format: {ext}")

One dispatcher, each parser is its own function. Each returns the same list[dict]
structure so downstream code doesn't need to know which format it came from.

Me:
for pdfs specifically, some of them are scanned so pdfminer cant read them. how do
i handle that automatically like without the user having to specify which ones are scans

Claude:
Check per page, not per document — some PDFs mix scanned and text pages.
Use pymupdf to extract text and check the character count:

    def is_scanned_page(page, min_char_count: int = 40) -> bool:
        try:
            text = page.get_text("text").strip()
            if len(text) >= min_char_count:
                return False
            images = page.get_images()
            return len(images) > 0 or len(text) == 0
        except Exception:
            return False

If a page has fewer than 40 characters but has embedded images, treat it as
scanned and run OCR on it. 40 is a conservative threshold — you can tune it.

Me:
and also for the filenames of scanned pdfs, some have "scan" in the name. should
i detect that too or just rely on the page level check

Claude:
Both. Do a filename check first as a fast path — if the name contains "scan" or
has the ".scan.pdf" pattern, treat the whole document as scanned from the start
and skip the per-page text extraction attempt:

    def detect_document_type(file_path: Path) -> str:
        name = file_path.name.lower()
        if ".scan.pdf" in name or "_scan" in name or "scan" in name:
            return "scan"
        ext = file_path.suffix.lower()
        if ext == ".pdf":
            return "pdf"
        elif ext == ".docx":
            return "docx"
        elif ext == ".md":
            return "md"
        return "txt"

For documents where the type is "scan", skip the text extraction entirely and
go straight to OCR on all pages. For type "pdf", still do the per-page check
because they might be hybrid.

Me:
makes sense. how do i detect document type separate from the file extension check

Claude:
For a hackathon with a known corpus, extension-based detection is fine — don't

    import magic

That gives you "application/pdf", "application/vnd.openxmlformats..." etc.
Only add this if you actually see extension mismatches in your corpus.
For the Ashen Era Archive with 415 files of known provenance, the extension

Chunk IDs and Metadata Design
--------------------------------------------------------------------------------

Me:
for chunk ids should i use uuid4 or some kind of deterministic slug. the problem with
uuid is every time we rerun the pipeline we get new ids and chromadb accumulates
duplicates

Claude:
Use a deterministic slug. UUIDs break idempotency — reruns create duplicates.
Build the ID from source filename + page + chunk index:

    import re
    from pathlib import Path

    def sanitize_id(text: str) -> str:
        text = text.lower()
        text = re.sub(r'[^a-z0-9_]+', '_', text)
        text = re.sub(r'_+', '_', text).strip('_')
        return text[:60] if text else "chunk"

    def make_chunk_id(filepath: Path, page: int, chunk_idx: int) -> str:
        base = sanitize_id(filepath.stem)
        return f"{base}_p{page}_c{chunk_idx}"

Result: "codex_vaeloria_weapons_p4_c2" — human-readable, stable across reruns.
Use get_or_create_collection in ChromaDB and it won't insert duplicates.

Me:
also we need to assign reliability tiers to chunks based on which folder they come
from. codex docs are authoritative, wiki is secondary, chronicles are narrative,
ephemera stuff is unreliable. how do we classify this automatically from the path

Claude:
Path-based heuristics work perfectly for your corpus structure.
Map folder names and filename patterns to reliability tiers:

    def assign_source_reliability(file_path: Path) -> str:

        elif "wiki" in path_str:

        elif "chronicles" in path_str:
            return "novel"
        elif "trial" in name_str or "court_martial" in name_str:
            return "ephemera_trial"
        elif "ballad" in name_str or "tavern" in name_str or "song" in name_str:
            return "ephemera_tavern"
        elif "ledger" in name_str or "manifest" in name_str:
            return "ephemera_ledger"
        elif "letter" in name_str or "dispatch" in name_str:
            return "ephemera_letter"
        elif "catalogue" in name_str or "auction" in name_str:
            return "ephemera_catalogue"
        elif "ephemera" in path_str:
            return "ephemera"
        return "unknown"

Store this as a string in chunk metadata. The reranker will apply a numeric
multiplier (1.10 for official_codex, down to 0.85 for ephemera_tavern) at

Hierarchical Chunking Strategy
--------------------------------------------------------------------------------

Me:
for chunking the text after parsing, whats the best chunk size. we tried 500 tokens
but some answers span across chunk boundaries

Claude:
The boundary problem is real. Two fixes:

1. Chunk by section first (use headers as natural break points), then
   split oversized sections by character limit as a fallback.

2. Add overlap — when you split a section into multiple chunks,
   carry the last N characters of the previous chunk into the next one:

    CHUNK_SIZE = 800       # characters
    CHUNK_OVERLAP = 150    # characters

    def split_with_overlap(text: str, size=CHUNK_SIZE, overlap=CHUNK_OVERLAP) -> list[str]:
        chunks = []
        start = 0
        while start < len(text):
            end = start + size
            chunks.append(text[start:end])
            start = end - overlap
        return chunks

800 chars / 150 overlap works well for lore documents with mixed-length paragraphs.
The overlap ensures that an answer straddling two chunks is fully captured in
at least one of them.

Me:
for markdown files the headers are natural section boundaries. how do i split on
those cleanly

Claude:
Use regex to find all heading markers and split on them:

    import re

    def chunk_markdown_by_section(text: str) -> list[dict]:
        # Split on H1, H2, H3 headings
        pattern = r'(?=^#{1,3}\s)', flags=re.MULTILINE
        sections = re.split(pattern, text, flags=re.MULTILINE)

        chunks = []
        for section in sections:
            section = section.strip()
            if not section:
                continue
            # Extract heading as section_title
            lines = section.split('\n', 1)
            title = lines[0].lstrip('#').strip()
            body = lines[1].strip() if len(lines) > 1 else ""
            chunks.append({"section_title": title, "content": body})

        return chunks

This gives you clean section_title metadata on every chunk, which is gold
for your reranker — it can match query keywords against section titles with
a bonus score.

Me:
and for docx files, how do we extract the section structure. paragraphs dont have
header markers the same way markdown does

Claude:
python-docx exposes paragraph styles. Headings have styles like "Heading 1",
"Heading 2" etc:

    from docx import Document

    def parse_docx(filepath: Path) -> list[dict]:
        doc = Document(str(filepath))
        sections = []
        current_section = {"title": "", "content": []}

        for para in doc.paragraphs:
            style = para.style.name.lower()
            if "heading" in style:
                if current_section["content"]:
                    sections.append(current_section)
                current_section = {"title": para.text.strip(), "content": []}
            else:
                if para.text.strip():
                    current_section["content"].append(para.text.strip())

        if current_section["content"]:
            sections.append(current_section)

        return [
            {"section_title": s["title"], "content": "\n".join(s["content"])}
            for s in sections
        ]

If the DOCX has no heading styles (flat formatting), fall back to paragraph-based
chunking with overlap. Check len(sections) after parsing — if it's 1 or 0,
the document has no styled headings and you need the fallback.

OCR Engine — Tesseract and Image Preprocessing

Me:
we installed tesseract but pytesseract cant find it. how do we make the path detection
work on both mac and windows without hardcoding

Claude:
Use shutil.which first (respects PATH), then check common install locations:

    import shutil, os
    from pathlib import Path

    COMMON_TESSERACT_PATHS = [
        os.getenv("TESSERACT_CMD", ""),
        os.getenv("TESSERACT_PATH", ""),
        "C:\\Program Files\\Tesseract-OCR\\tesseract.exe",
        "C:\\Program Files (x86)\\Tesseract-OCR\\tesseract.exe",
        "/usr/bin/tesseract",
        "/usr/local/bin/tesseract",
        "/opt/homebrew/bin/tesseract",
    ]

    def find_tesseract_binary() -> str | None:
        which_cmd = shutil.which("tesseract")
        if which_cmd and os.path.isfile(which_cmd):
            return which_cmd
        for candidate in COMMON_TESSERACT_PATHS:
            if candidate and os.path.isfile(candidate):
                return candidate
        return None

Then on init:
    cmd = find_tesseract_binary()
    if cmd:
        pytesseract.pytesseract.tesseract_cmd = cmd

Also add TESSERACT_CMD to .env.example so teammates can override it
without touching code.

Me:
the ocr on dark or blurry pages is terrible. just getting random characters.
what preprocessing should we apply

Claude:
For degraded historical document scans, this preprocessing pipeline works well:

1. Grayscale conversion
2. Upscale to at least 1000px wide (low DPI kills OCR)
3. Contrast enhancement
4. Sharpening
5. Binarization — threshold out the parchment/paper background color

    from PIL import Image, ImageEnhance, ImageFilter

    def preprocess_image_for_ocr(
        image_input,
        contrast_factor: float = 1.8,
        upscale_min_width: int = 1000,
        binarize_threshold: int = 140
    ) -> Image.Image:
        if isinstance(image_input, (str, Path)):
            img = Image.open(str(image_input))
        else:
            img = image_input.copy()

        if img.mode != "L":
            img = img.convert("L")

        width, height = img.size
        if width < upscale_min_width:
            scale = upscale_min_width / max(width, 1)
            new_size = (int(width * scale), int(height * scale))
            img = img.resize(new_size, resample=Image.Resampling.BILINEAR)

        enhancer = ImageEnhance.Contrast(img)
        img = enhancer.enhance(contrast_factor)
        img = img.filter(ImageFilter.SHARPEN)

        table = [0 if i < binarize_threshold else 255 for i in range(256)]
        img = img.point(table, "1")

        return img

The binarize threshold of 140 removes parchment tint. Go lower (120) if text
is getting wiped out, higher (160) if background noise is still coming through.

Me:

Claude:
    pix = page.get_pixmap(dpi=150)

Claude:
Pass it in the custom config string to pytesseract:

Extracting Figure Plates from PDFs
--------------------------------------------------------------------------------

Me:
so my job is to extract all the images and figure plates from our pdf corpus and store
them properly. how do i do this with pymupdf because some pdfs have embedded images
and some have images that are part of the page render

Claude:
pymupdf handles both. For embedded images (stored in the PDF's XObject table),
use get_images() + extract_image():

    import fitz
    from PIL import Image
    import io

    def extract_images_from_pdf(pdf_path: str, output_dir: str) -> list[dict]:
        doc = fitz.open(pdf_path)
        extracted = []

        for page_num, page in enumerate(doc):
            for img_index, img in enumerate(page.get_images(full=True)):
                xref = img[0]
                base_image = doc.extract_image(xref)
                img_bytes = base_image["image"]
                ext = base_image["ext"]

                pil_img = Image.open(io.BytesIO(img_bytes))
                w, h = pil_img.size

                # skip tiny decorators and icons
                if w < 100 or h < 100:
                    continue

                filename = f"page{page_num+1}_img{img_index+1}.{ext}"
                out_path = os.path.join(output_dir, filename)
                with open(out_path, "wb") as f:
                    f.write(img_bytes)

                extracted.append({
                    "page": page_num + 1,
                    "path": out_path,
                    "width": w,
                    "height": h
                })

        return extracted

For images that are rendered as page content (not embedded), render the whole
page to an image with page.get_pixmap() and save that. Those are usually the
full-page plates you want to keep anyway.

Me:
some of the images are coming out very small like 20x20 pixels and they are clearly
just borders or bullet decorators. how do i filter them out properly

Claude:
The 100x100 pixel filter catches most of them. But also check aspect ratio —
legitimate figure plates are generally close to square or landscape. Extreme
aspect ratios (very tall and thin, or very wide and flat) are usually decorative
dividers:

    def is_meaningful_image(pil_img: Image.Image) -> bool:
        w, h = pil_img.size
        if w < 100 or h < 100:
            return False
        aspect = max(w, h) / max(min(w, h), 1)
        if aspect > 8:
            return False   # extreme banner/divider shape
        return True

Also filter by file size after saving — images under ~3KB are usually
low-detail decorators. You can check len(img_bytes) < 3000 before saving.

Me:
ok and i need to generate captions for each extracted image. some images have a
caption text right below them in the pdf. how do i capture that

Claude:
After extracting an image, check the text near that image's bounding box on the page.
pymupdf lets you get text blocks with their coordinates:

    def get_caption_near_image(page, img_rect, search_margin: int = 60) -> str:
        # Look for text below the image bounding box
        below_rect = fitz.Rect(
            img_rect.x0,
            img_rect.y1,
            img_rect.x1,
            img_rect.y1 + search_margin
        )
        text = page.get_text("text", clip=below_rect).strip()
        return text if len(text) > 5 else ""

This checks a 60-pixel strip below the image for caption text. Adjust
search_margin if your plates have wider spacing. Also check above the image
(some codex plates have titles above, captions below).

Table Extraction and Markdown Conversion
--------------------------------------------------------------------------------

Me:
for the tables inside the pdfs and docx files, how do we extract them properly.
pdfplumber was suggested but some tables dont have visible borders

Claude:
pdfplumber is solid for lattice tables (visible borders). For borderless tables,
try camelot with stream flavor:

    import camelot

    def extract_tables_from_pdf(pdf_path: str, pages: str = "all") -> list[str]:
        md_tables = []

        # Try lattice first (bordered tables)
        try:
            tables = camelot.read_pdf(str(pdf_path), pages=pages, flavor="lattice")
            for table in tables:
                if table.parsing_report["accuracy"] > 70:
                    md_tables.append(table.df.to_markdown(index=False))
        except Exception:
            pass

        # Fall back to stream for borderless
        if not md_tables:
            try:
                tables = camelot.read_pdf(str(pdf_path), pages=pages, flavor="stream")
                for table in tables:
                    md_tables.append(table.df.to_markdown(index=False))
            except Exception:
                pass

        return md_tables

Converting to markdown with table.df.to_markdown(index=False) is the right
move — GitHub markdown tables are readable as plain text for embedding AND
render beautifully in Streamlit.

Me:
for docx tables, how do we get them out with python-docx

Claude:
python-docx exposes tables through doc.tables — each table has rows and cells:

    from docx import Document

    def extract_tables_from_docx(filepath: Path) -> list[str]:
        doc = Document(str(filepath))
        md_tables = []

        for table in doc.tables:
            rows = []
            for i, row in enumerate(table.rows):
                cells = [cell.text.strip().replace("\n", " ") for cell in row.cells]
                rows.append("| " + " | ".join(cells) + " |")
                if i == 0:
                    # Add markdown header separator after first row
                    separator = "| " + " | ".join(["---"] * len(cells)) + " |"
                    rows.append(separator)

            if rows:
                md_tables.append("\n".join(rows))

        return md_tables

Clean cell text by stripping newlines (multi-line cells break markdown tables).

Adaptive K Budgeting — Intent Classification
--------------------------------------------------------------------------------

Me:
we want the number of chunks retrieved (k) to be dynamic based on query type.
visual queries need k=2, comparative k=6 to 8, single fact k=2, standard k=4.

Claude:
Rule-based classification on the lowercased query. Check in priority order
(visual first since those are most specific):

    def determine_query_intent_and_budget(
        query: str,
        entities: list = None,
        fields: list = None
    ) -> dict:
        q = query.lower().strip()

        # Visual intent — figure plates, maps, portraits, banners
        visual_kw = ["diagram", "blueprint", "schematic", "figure plate", "plate",
                     "drawing", "illustration", "image", "photo", "map", "portrait",
                     "banner", "emblem", "crest", "heraldry"]
        if any(re.search(r"\b" + re.escape(v) + r"\b", q) for v in visual_kw):
            return {"intent": "visual", "target_k": 2, "min_k": 1}

        # Single fact — dates, names, locations
        single_kw = ["when was", "what year", "who is", "who was", "where was",
                     "born in", "died in"]
        is_single = any(q.startswith(k) or k in q for k in single_kw)
        is_not_comparative = not any(k in q for k in ["compare", "difference", "versus"])
        if is_single and is_not_comparative:
            return {"intent": "single_fact", "target_k": 2, "min_k": 1}

        # Comparative — multiple entities or explicit compare keywords
        ent_count = len(entities) if entities else 0
        if ent_count >= 2 or any(k in q for k in ["compare", "versus", "vs", "difference between"]):
            target_k = min(8, max(6, ent_count * 3))
            return {"intent": "comparative", "target_k": target_k, "min_k": 2}

        # Quantitative / aggregation
        quant_kw = ["total", "sum", "average", "how many", "count", "aggregate", "ledger"]
        if any(re.search(r"\b" + re.escape(k) + r"\b", q) for k in quant_kw):
            return {"intent": "quantitative_or_multihop", "target_k": 6, "min_k": 2}

        return {"intent": "standard_narrative", "target_k": 4, "min_k": 2}

Entire function runs in microseconds. No model call, no API cost.

    KNOWN_ENTITIES = [
        "Ignatz Ashgrove the Oathless", "Aldous Wrenfield the Last Warden",
        "House Morvain", "The Ashen Vanguard", "Greyfell Citadel",
        "Thrice-Bound Edge", "Thrice-Bound Lantern", "Weeping Lurker",

Cross-Relevance Reranking
--------------------------------------------------------------------------------

Me:
for the reranker, how do we combine entity matching score, keyword coverage and
the base vector score into one number. what weights work best

Claude:
Additive composite where entity bonuses accumulate on top of the weighted base:

    def compute_cross_relevance(query: str, chunk: dict) -> float:
        q_clean = query.lower().strip()
        keywords = extract_meaningful_keywords(q_clean)   # strip stopwords
        entities = extract_entities(query)
        fields = extract_fields(query)

        content = str(chunk.get("content", "")).lower()
        doc_name = str(chunk.get("document_name", "")).lower()
        caption = str(chunk.get("caption", "") or "").lower()
        section = str(chunk.get("section_title", "") or "").lower()
        full_text = f"{doc_name} {caption} {section} {content}"
        modality = str(chunk.get("modality", "text"))

        # 1. Entity bonus (additive per entity)
        entity_bonus = 0.0
        has_entity_hit = False
        matched_count = 0
        for ent in entities:
            if ent.lower() in full_text:
                entity_bonus += 0.50
                has_entity_hit = True
                matched_count += 1
            else:
                # Partial token match
                toks = [t for t in ent.split() if len(t) > 3]
                if toks and all(t.lower() in full_text for t in toks):
                    entity_bonus += 0.35
                    has_entity_hit = True
                    matched_count += 1

        # Multi-entity intersection bonus
        if matched_count >= 2:
            entity_bonus += 0.40

        # 2. Dossier bonus (doc named after queried entity)
        dossier_bonus = 0.0
        for ent in entities:
            ent_norm = ent.replace(" ", "_").replace("-", "_").lower()
            doc_norm = doc_name.replace("-", "_")
            if ent_norm in doc_norm:
                dossier_bonus += 0.35
                break

        # 3. Field match bonus
        field_bonus = sum(
            0.25 for f in fields
            if any(a in full_text for a in KNOWN_FIELDS.get(f, [f]))
        )

        # 4. Keyword coverage
        if not keywords:
            kw_coverage = 0.5
        else:
            found = sum(1 for kw in keywords if re.search(r"\b" + re.escape(kw) + r"\b", full_text))
            kw_coverage = found / len(keywords)

        # 5. Phrase bonus
        phrase_bonus = 0.0
        if len(keywords) >= 2:
            phrase = " ".join(keywords[:3])
            if phrase in content or phrase in caption:
                phrase_bonus = 0.35

        # 6. Base scores
        base_score = float(chunk.get("relevance_score", 0.5) or 0.5)
        raw_sim = float(chunk.get("raw_similarity", 0.5) or 0.5)

        # 7. Modality boost
        modality_bonus = 0.15 if (chunk.get("media_path") and modality in ("image-caption", "table")) else 0.0

        # 8. Reliability multiplier
        reliability = str(chunk.get("source_reliability", "")).lower()
        rel_mult = 1.1 if ("official" in reliability or "codex" in reliability) else \
                   0.85 if ("ballad" in reliability or "tavern" in reliability) else 1.0

        # 9. Entity penalty
        entity_penalty = 0.2 if (entities and not has_entity_hit and len(keywords) > 0) else 1.0

        cross_score = (
            (base_score * 0.25) +
            (raw_sim * 0.20) +
            (kw_coverage * 0.25) +
            entity_bonus +
            dossier_bonus +
            field_bonus +
            phrase_bonus +
            modality_bonus
        ) * rel_mult * entity_penalty

        return round(cross_score, 4)

Elbow Method Score Drop-Off and Token Budget
--------------------------------------------------------------------------------

Me:
after reranking we want to prune trailing low-relevance chunks. we're calling this
the elbow method. basically drop chunks whose score falls below a fraction of the
top score. how do i implement that

Claude:
    def apply_relative_score_dropoff(
        chunks: list[dict],
        alpha: float = 0.60,
        min_k: int = 1,
        max_k: int = 8
    ) -> list[dict]:
        if not chunks:
            return []

        sorted_chunks = sorted(
            chunks,
            key=lambda x: float(x.get("relevance_score", 0.0) or 0.0),
            reverse=True
        )

        top_score = float(sorted_chunks[0].get("relevance_score", 0.0))
        if top_score <= 0.0:
            return sorted_chunks[:min_k]

        threshold = top_score * alpha
        retained = []

        for i, c in enumerate(sorted_chunks):
            c_score = float(c.get("relevance_score", 0.0) or 0.0)
            if i < min_k:
                retained.append(c)
                continue
            if len(retained) >= max_k:
                break
            if c_score >= threshold:
                retained.append(c)
            else:
                logger.debug(f"Drop-off at chunk {i+1}: score {c_score:.3f} < threshold {threshold:.3f}")
                break

        return retained

alpha=0.60 means keep chunks within 60% of top score. Good starting value.
Run your eval on 0.55, 0.60, 0.65 and pick the best for your 20 questions.

Me:
and after the elbow pruning, we also want to cap the total tokens sent to the LLM
to avoid slow generation. how to do that without a proper tokenizer

Claude:
Heuristic tokenization — 1 word ≈ 1.33 tokens. Close enough for a context budget:

    def apply_token_budget_packing(
        chunks: list[dict],
        max_tokens: int = 2500
    ) -> list[dict]:
        packed = []
        current_tokens = 0

        for c in chunks:
            text = str(c.get("content", "")) + " " + str(c.get("caption", "") or "")
            word_count = len(text.split())
            est_tokens = max(int(word_count * 1.33), 10)

            if packed and (current_tokens + est_tokens > max_tokens):
                logger.debug(f"Token budget reached ({current_tokens} tokens). Stopping.")
                break

            packed.append(c)
            current_tokens += est_tokens

        return packed

2500 tokens leaves comfortable room for the system prompt + user query +
generation output within a typical 8k context window. Adjust if you switch models.

Me:
for CRAG we want to evaluate retrieval quality before calling the LLM. three verdicts:
CORRECT, AMBIGUOUS, OUT_OF_DOMAIN. how do we compute this from just the vector scores
without another model call

Claude:
Read the raw_similarity you already computed during ChromaDB retrieval.
No second model call needed:

    def evaluate_retrieval_confidence(
        query: str,
        retrieved_chunks: list[dict],
        threshold: float = 0.28
    ) -> dict:
        if not retrieved_chunks:
            return {
                "verdict": "OUT_OF_DOMAIN",
                "is_in_domain": False,
                "confidence_score": 0.0,
                "top_similarity": 0.0
            }

        top_sim = max(
            float(c.get("raw_similarity", 0.0) or 0.0)
            for c in retrieved_chunks
        )

        # Count how many retrieved chunks contain known corpus entities
        all_text = " ".join(str(c.get("content", "")) for c in retrieved_chunks).lower()
        entities = extract_entities(query)
        entity_presence = sum(1 for e in entities if e.lower() in all_text)
        entity_ratio = entity_presence / max(len(entities), 1)

        if top_sim >= 0.45 and (not entities or entity_ratio > 0.0):
            verdict = "CORRECT"
        elif top_sim >= 0.28:
            verdict = "AMBIGUOUS"
        else:
            verdict = "OUT_OF_DOMAIN"

        return {
            "verdict": verdict,
            "is_in_domain": verdict != "OUT_OF_DOMAIN",
            "confidence_score": round(top_sim, 4),
            "top_similarity": round(top_sim, 4)
        }

CORRECT → pass to LLM normally.
AMBIGUOUS → pass to LLM, but add a note that some context may be missing.
OUT_OF_DOMAIN → skip LLM entirely, return the standard refusal message.

Me:
streamlit reruns the whole script every time a user sends a message. this means
chromadb and the embedding model reload every single interaction. how to fix

Claude:
st.cache_resource is exactly for this — it caches non-serializable objects
(models, DB connections) for the lifetime of the Streamlit server process:

    import streamlit as st

    @st.cache_resource
    def load_retrieval_pipeline():
        from src.retrieval.retriever import get_collection
        return get_collection()   # ChromaDB collection, cached permanently

    @st.cache_resource
    def load_embedding_function():
        from src.retrieval.indexer import get_embedding_function
        return get_embedding_function()   # BGE model, cached permanently

    @st.cache_resource
    def load_groq_client():
        from groq import Groq
        import os
        return Groq(api_key=os.getenv("GROQ_API_KEY"))

Call these at the top of your app.py. They execute once on first load,
then return the cached object on every subsequent rerun. Zero reload cost.

    # At top of app.py
    collection = load_retrieval_pipeline()
    groq_client = load_groq_client()

Do NOT use @st.cache_data for models or DB connections — it tries to
serialize them and throws errors. cache_resource = for objects,
cache_data = for data.

Me:
for rendering inline images in the answer, the LLM generates markdown image syntax
like ![caption](path). how do we make streamlit actually render those

Claude:
st.markdown() renders markdown image syntax natively as long as the path is
accessible. For local file paths, Streamlit needs to serve them — either put
them in the static folder or use st.image() for programmatic rendering.

The cleaner approach: post-process the LLM response to extract image paths
and render them separately with st.image():

    import re

    def render_answer_with_images(answer_text: str):
        # Find all ![caption](path) patterns
        img_pattern = re.compile(r'!\[([^\]]*)\]\(([^)]+)\)')
        parts = img_pattern.split(answer_text)

        # Parts alternates: text, caption, path, text, caption, path, ...
        i = 0
        while i < len(parts):
            if i % 3 == 0:
                # Text part
                if parts[i].strip():
                    st.markdown(parts[i])
            elif i % 3 == 2:
                # Path part (caption is i-1)
                caption = parts[i-1]
                path = parts[i]
                if os.path.exists(path):
                    st.image(path, caption=caption, use_column_width=True)
            i += 1

This gives you clean image rendering with proper captions in Streamlit
even for local file paths.

    import json, time
    from pathlib import Path

    def run_evaluation(
        questions_path: str,
        output_path: str,
        retriever,
        generator
    ) -> dict:
        with open(questions_path) as f:
            questions = json.load(f)

        results = []
        passed = 0

        for q in questions:
            qid = q["qid"]
            question = q["question"]
            track = q["track"]

            try:
                start = time.perf_counter()
                chunks = retriever.retrieve(question)
                answer = generator.generate(question, chunks)
                latency = time.perf_counter() - start

                result = {
                    "qid": qid,
                    "track": track,
                    "question": question,
                    "answer": answer,
                    "retrieved_sources": [c.get("document_name") for c in chunks],
                    "retrieved_pages": [c.get("page_number") for c in chunks],
                    "chunks_retrieved": len(chunks),
                    "latency_s": round(latency, 3),
                    "has_media": any(c.get("media_path") for c in chunks),
                }
                results.append(result)
                passed += 1
                print(f"[OK] {qid} ({track[:20]}): {latency:.2f}s, {len(chunks)} chunks")

            except Exception as e:
                results.append({"qid": qid, "error": str(e), "question": question})
                print(f"[ERROR] {qid}: {e}")

        summary = {
            "total": len(questions),
            "passed": passed,
            "failed": len(questions) - passed,
            "avg_latency_s": round(
                sum(r.get("latency_s", 0) for r in results if "latency_s" in r) / max(passed, 1),
                3
            )
        }

        output = {"summary": summary, "results": results}
        with open(output_path, "w") as f:
            json.dump(output, f, indent=2)

        print(f"\n=== Evaluation Complete ===")
        print(f"Passed: {passed}/{len(questions)}")
        print(f"Avg latency: {summary['avg_latency_s']}s")
        return summary

        correct = 0

Me:
how do we handle the case where the groq api rate limits us during evaluation

Claude:
Add a small sleep between calls and wrap in retry logic:

    import time

    def call_groq_with_retry(messages, model, max_retries=3, delay=2.0):
        for attempt in range(max_retries):
            try:
                response = groq_client.chat.completions.create(
                    model=model,
                    messages=messages,
                    max_tokens=800,
                    temperature=0.1,
                )
                return response.choices[0].message.content
            except Exception as e:
                if "rate_limit" in str(e).lower() or "429" in str(e):
                    print(f"Rate limited. Waiting {delay}s before retry {attempt+1}...")
                    time.sleep(delay)
                    delay *= 2   # exponential backoff
                else:
                    raise

        raise RuntimeError(f"Failed after {max_retries} retries")

Groq's free tier allows 30 requests/minute. 20 questions with 1-2s latency
each should be well within limits. But having the retry logic is good practice
anyway — network hiccups also trigger it.
